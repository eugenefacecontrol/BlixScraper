# BlixScraper

Локальный помощник для продуктовых покупок в Польше: публичные газетки Blix → SQLite → четыре MCP-инструмента. Работает без OpenAI/Gemini API для поиска и расчётов. Python 3.11+, macOS; зависимости устанавливаются только в `.venv`.

```sh
uv sync --extra dev
cp config.example.toml config.toml
uv run blix refresh
uv run blix status
uv run blix search 'масло'
uv run blix compare examples/basket.json
uv run blix serve --transport streamable-http
```

HTTP MCP слушает только `127.0.0.1:8765/mcp`; остановка Ctrl+C. Альтернатива: `uv run blix serve` для stdio. `scripts/run-local.sh` запускает HTTP после установки. Никакие глобальные настройки не изменяются. `uv.lock` закрепляет зависимости. SQLite и кэш HTML находятся в `data/` и исключены из Git.

## Что получается

`search_offers` возвращает действующие предложения, цену из JSON, даты, источник и статус проверки. `get_offer` даёт исходный JSON, изображение товара и полной страницы, координаты и локальные доказательства. `data_status` показывает время получения, старые данные, обнаруженные газетки и ошибки. `compare_basket` возвращает варианты одного магазина, лучшую **полную** корзину для ≤ N магазинов, отдельные неполные суммы и предложения без подтверждённой стоимости.

Числа в `display_price_pln` нельзя автоматически считать ценой упаковки. Ни масса, ни условия карты, ни минимальная покупка не угадываются. По умолчанию все предложения требуют просмотра газетки. Это важное ограничение первой версии: без подтверждения условий поиск работает, но достоверная корзина может отсутствовать. Помощник не выполняет автоматическое OCR всего каталога.

## Подтверждение предложения

Просмотрите `source_url`, `image_url` и `leaflet_page_image_url` из `uv run blix offer ID`. Проверьте товар, массу/объём, цену за упаковку или единицу, даты и весь мелкий текст. Создайте локальный JSON по `examples/evidence.example.json`, затем:

```sh
uv run blix review ID /absolute/path/to/review.json
```

`review` доступен только локально, не через MCP. Он сохраняет точный снимок исходного предложения; изменение исходных данных отменяет подтверждение. Это записанная визуальная проверка, а не независимая гарантия магазина. Проверенные примеры от 05.10.2026 и воспроизводимый расчёт находятся в [docs/validation.md](docs/validation.md).

Поля доказательства:

- `price_grosz`: подтверждённая целая цена в грошах; `basis`: `package` либо `per_unit`.
- `unit`: `kg`, `l`, `piece`; для упаковки `package_quantity` в этой единице.
- `min_packs`, `max_packs`: подтверждённые минимальное и максимальное число упаковок.
- `buy`, `free`: акция на одинаковый SKU, например 2+1. Другие сложные акции не добавляйте в эту схему.
- `required_cards`, `required_coupons`: точные названия необходимых карт и активированных купонов.
- `max_quantity`: предел количества в kg/l/piece; превышение исключает предложение, обычная цена сверх лимита не предполагается.
- `required_confirmations`: факты, которые пользователь должен подтвердить, например `kaufland_first_receipt_today`.
- `fat_percent`, `source_url`, `note`, `conditions_complete: true`: признаки товара, источник и запись проверки.

Если хотя бы одно существенное условие нельзя выразить или прочитать, оставьте предложение без подтверждения. Данные из сайта рассматриваются как недоверенный текст, не как инструкции.

## Корзина

Скопируйте `examples/basket.json`. Количество задаётся в kg/l/piece: 400 г → `0.4 kg`, 500 мл → `0.5 l`. Для требований используйте `fat_percent`, `required_terms`, `excluded_terms`. Допустимые замены задаются явно через `alternatives`; для конкретных вариантов — `offer_ids`. ChatGPT переводит русский запрос на польский и выделяет признаки; встроенные русские словарные варианты — только небольшая подстраховка.

Код считает целые упаковки, лишнее количество, итоговую сумму и эффективную цену за единицу через Decimal. Акции применяются только при соблюдении подтверждённых условий. Для каждого сочетания магазинов выбирается самый дешёвый подходящий SKU на каждую строку. Доступно 1–4 магазина, до 20 строк и до 12 настроенных сетей. Одна строка не делится между разными SKU/магазинами. Перекрывающиеся строки отклоняются: объедините количество или уточните варианты, чтобы не использовать лимит акции дважды.

`best_complete: null` означает, что подтверждённой полной корзины нет. Сумма неполного варианта — только `partial_subtotal`. Данные Blix не подтверждают наличие товара в конкретном магазине, полный ассортимент или минимальную цену в Польше. Правильная формулировка: «самый дешёвый вариант среди проверенных предложений».

## Сбор и ограничения

Сбор читает robots.txt, страницы выбранных сетей и все обнаруженные действующие газетки. Даты — Europe/Warsaw. Следует только ссылкам страниц, реально присутствующим в HTML; не использует `/api/*`, закрытые API, обход CAPTCHA или блокировок. HTTP 401/403/429 прекращает дальнейшие запросы к этой сети в текущем запуске. Перенаправления не проходят автоматически. Частота запросов координируется локальной файловой блокировкой между процессами с общей БД. По умолчанию запросы не чаще одного в 2 секунды, кэш HTML — 6 часов.

Точные повторные вхождения удаляются по стабильному ID. Разные вхождения товара в разных газетках сохраняются с собственными датами и доказательствами; одинаковое название не доказывает одинаковые условия. Старые данные сохраняются при ошибке обновления и явно помечаются; предложения старше 24 часов не участвуют в подтверждённой корзине. Настройки изменяются в `config.toml`.

Получение всех видимых газеток не доказывает полноту Blix. `catalog_complete` и `discovery_complete` остаются false. Отчёт показывает неизвестные даты, количество страниц, ошибки и достижение лимита. Нулевая выдача не означает отсутствие товара в магазине.

## Подключение и тесты

[Подключение к обычному ChatGPT](docs/chatgpt.md) · [Готовые русские инструкции](docs/assistant-instructions.ru.md) · [Исследование источников](docs/research.md) · [Результаты проверки](docs/validation.md).

```sh
uv run pytest -q
```

Тесты покрывают упаковки, 2+1, карты, купоны, лимиты, жирность, замены, неполную корзину, свежесть, JSON-парсер, ссылки на страницы, кэш, блокировки и настоящий MCP stdio-протокол. CI выполняет тот же набор без запросов к Blix.

Акция «каждая вторая упаковка дешевле» поддерживается через `pack_price_cycle_grosz`: например `[1349, 649]` — первая упаковка 13,49 zł, вторая 6,49 zł, третья снова 13,49 zł. Это явно проверенный повторяющийся цикл для одинакового SKU; его нельзя совмещать с `buy/free`. Для Aldi Wesoły Kurnik (05–10.10.2026) сохранён визуально проверенный пример: 2 упаковки по 10 яиц = 19,98 zł. Условия отсутствуют в исходном JSON. Автоматическое OCR новых предложений не реализовано; для нового вхождения условия снова требуют проверки.
